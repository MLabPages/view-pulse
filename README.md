# ViewPulse

端末内の画像・動画またはYouTube動画を大きく表示しながら、内カメで表情と推定視線を端末内解析するWebアプリです。

## 主な機能

- 端末内の画像または動画を選び、全画面に近い表示で閲覧
- YouTube URL、短縮URL、Shorts URLを公式埋め込みプレイヤーで再生
- YouTubeの再生時間と分析データを同期
- 対応端末では、インストールしたPWAをYouTubeの共有先として起動
- 内カメ1台とMediaPipe Face Landmarker、WebEyeTrack（BlazeGaze）による表情・推定視線の端末内解析
- 動画は再生時間、画像は記録開始からの経過時間と分析データを同期
- 記録中の内カメを「小さなピクチャーインピクチャ」と「完全に隠して解析中バーだけ」から選択し、途中でも切替
- 黒背景で9点をランダムに3巡するテンポ重視のキャリブレーションと、別の4点による精度確認（低精度時も注意表示付きで記録可能）
- 本測定中は調整時の顔位置を示す薄いガイドを表示し、通常の姿勢変化は信頼度を下げて残し、大きな変化だけ除外
- コンテンツ上の視線ヒートマップ、反応タイムライン、注視率・笑顔率・最多注視領域
- 明示的に同意した場合だけ表情映像を保存
- 表情を大きく、表示コンテンツを小窓にしたリアクション映像の再生・書き出し
- IndexedDBの端末内ライブラリから再表示、共有、削除
- YouTube記録は映像を複製せず、URL・動画ID・分析値だけを端末内保存
- 旧版の `rear_blob`（外カメ動画）を新しい表示コンテンツとして読み込む非破壊の互換処理

## プライバシー

- 選択した端末内ファイル、内カメ映像、分析値は外部へ送信しません。
- YouTube選択時は公式プレイヤーで動画を再生するためYouTubeへ接続します。カメラ映像と分析値はYouTubeへ送信しません。
- 内カメ映像は、利用者が「表情映像も端末内に保存する」を選んだ場合だけ記録します。
- 選ばない場合、内カメ映像はリアルタイム解析後に破棄され、数値だけが残ります。
- 記録終了後のデータは同じブラウザのIndexedDBへ保存されます。
- ブラウザのサイトデータ削除、プライベートブラウズ、端末の容量整理によりライブラリが消える場合があります。重要な記録は共有またはファイル保存も行ってください。
- 視線推定のWebEyeTrackモデルはこのアプリから端末へ読み込み、ブラウザのWorker内で処理します。MediaPipeのJavaScriptと顔モデルを読み込むため、初回にGoogle／jsDelivrのCDNへ接続します。選択コンテンツやカメラ映像は送信しません。

## YouTube共有から起動

対応ブラウザでViewPulseをPWAとしてインストールすると、YouTubeなどの共有メニューにViewPulseが表示されます。共有されたYouTube URLは開始画面へ自動入力されます。Web Share TargetはOS・ブラウザによって対応状況が異なり、すべてのiPhone・iPadでの表示は保証されません。

Netflixなど、公式の一般向け埋め込みプレイヤーを提供していない動画サービスには対応していません。

## Web版とiPhoneネイティブ版の役割

- **このWeb版**: 端末内の画像・動画・YouTube動画を表示し、**内カメ1台**で表情とおおまかな視線を記録します。前後カメラの同時利用を必要としないため、対応ブラウザで試せます。
- **iPhoneネイティブ版**: 別リポジトリの `view-pulse-ios` です。対応iPhoneでは前後カメラを同時に使い、**外カメで実際の場面、内カメで表情**を記録します。Web版とは入力する場面が異なります。

## 対応端末

カメラは内カメ1台だけを使うため、前後カメラ同時利用に由来する旧版のiPhone・iPad制限はありません。カメラとMediaRecorderに対応した主要ブラウザで利用できます。カメラ利用にはHTTPSまたはlocalhostが必要です。

## 視線ヒートマップの精度と使い方

視線ヒートマップは、目のランドマーク比率を式で補正する方式ではなく、**WebEyeTrack（BlazeGaze）による専用の推定モデル**を使います。モデルは内カメ画像、目の領域、顔の3D向きから生の推定視線を出し、ViewPulseが9点の実測値から動画内座標への変換を直接作ります。WebEyeTrack内部の追加学習と別の5点補正を重ねる方式ではありません。計算はブラウザ内のWorkerで行われ、カメラ映像を外部へ送ることはありません。

キャリブレーション開始時には顔位置ガイドを表示し、顔の中央位置・カメラとの距離・正面向きをそろえます。その後、動画やYouTube画像を黒背景で隠し、同じ9地点をランダム順で3回ずつ連続して測ります。各回は点の移動後に得られた3〜5サンプルの中央値を使います。PCでは点が光ったら見たままクリックし、iPhone・Androidでは端末が動かないよう自動確定します。9点の変換は一次・二次の候補を未使用点予測で比較し、過剰適合しにくい方を自動選択します。補正後は未使用の4点で精度確認を行い、平均ずれが動画対角線の12%以内、かつ各確認点のずれが18%以内なら「調整済み」、基準外なら「低精度」と表示します。

本測定中は、動画の左上にある薄い顔位置ガイドに、調整時の基準枠と現在位置の点を表示します。顔位置が少し変わったフレームを一律に捨てず、`gaze_pose_quality` と `gaze_weight` に信頼度を保存してヒートマップの濃さへ反映します。大きく姿勢が変わったフレームだけ視線点から除外します。視線が得られなかった理由は `gaze_missing_reason` に、顔未検出・モデル出力待ち・姿勢除外などを分けて保存します。これは自然な姿勢変化を許しながら、研究時に利用可能なデータを過度に減らさないための処理です。低精度の記録は、細かな注視点ではなく大きな領域（AOI）の傾向として扱ってください。全画面化・画面回転などで表示領域が変わった場合は補正を無効化し、再調整が必要です。

これは**推定視線**であり、専用アイトラッカーで測った注視点そのものではありません。照明、眼鏡、まばたき、顔の一部が隠れること、端末の揺れ、顔とカメラの距離・角度の大きな変化ではずれます。端末は顔からおおむね35〜60cm離し、顔全体が入るよう固定してください。精密な注視点、診断、感情の断定には使わず、必要に応じて専用機器や自己報告と併用してください。

### 利用している視線モデル

- [WebEyeTrack](https://github.com/RedForestAI/WebEyeTrack)（MIT License）を、ViewPulseの9点キャリブレーションに合わせてWorkerとして組み込んでいます。
- モデル資産とライセンスは `web/` と `vendor/webeyetrack/` に同梱しています。WebEyeTrackの論文・評価値を、ViewPulseの精度値として転用していません。

## 起動

```powershell
node local-server.mjs
```

PCでは `http://127.0.0.1:8765`、スマートフォンではHTTPSで公開したURLを開きます。

## 検証

```powershell
node --check app.js
node --check local-server.mjs
node verify.mjs
```
